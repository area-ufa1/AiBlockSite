# Страж вкладок — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Android-приложение, которое через службу доступности читает адрес и заголовок активной вкладки в любом браузере. Если страница попадает под включённую категорию, оно открывает claude.ai с поддерживающим промптом.

**Architecture:** Вся логика (нормализация, сопоставление по доменам и словам, конвейер с задержкой и защитой от повторов, промпты, разбор ответа Claude, разбор дерева экрана) лежит в чистом Kotlin/JVM-модуле `:core` и тестируется без Android. Модуль `:app` — тонкая оболочка: служба доступности превращает `AccessibilityNodeInfo` в `UiNode`, Room хранит категории и события блокировки, `TermuxClaudeClassifier` вызывает `claude -p` в Termux, экран на Compose показывает категории со статистикой и настройки.

**Tech Stack:** Kotlin 2.2.x, AGP 8.13.x, Gradle 8.14.3 (wrapper), JDK 17, Jetpack Compose (BOM) + Material 3 + Navigation Compose, Room 2.8.x через KSP, DataStore Preferences, kotlinx-coroutines; тесты на JUnit 4, kotlinx-coroutines-test и Robolectric (для `:app`). Версии фиксируются в `gradle/libs.versions.toml`: берём последние стабильные, которые реально скачиваются.

**Spec:** `docs/superpowers/specs/2026-10-03-tab-guard.md` (читать вместе с разделом «Решения, принятые при планировании»)

## Global Constraints

- Платформа — только Android. `minSdk = 26`, `targetSdk = compileSdk = 36`. Пакет `app.tabguard`.
- Механизм — Accessibility Service, без привязки к одному браузеру. Браузер — любой пакет, который обрабатывает `ACTION_VIEW` для `http://`.
- Срабатывает по событиям `TYPE_WINDOW_STATE_CHANGED | TYPE_WINDOW_CONTENT_CHANGED` с задержкой **500 мс** и защитой от повторов для одной и той же страницы.
- Категории ведёт человек. У каждой: имя, переключатель вкл/выкл, слова, домены, счётчик блокировок.
- Доступ к Claude только через `claude -p --model haiku` в Termux (интент `com.termux.RUN_COMMAND`). Токены, cookies и API-ключи не используем.
- Перекидываем на `https://claude.ai/new?q=<URL-encoded промпт>`, тот же промпт кладём в буфер обмена.
- Весь текст интерфейса и промптов на русском, в `res/values/strings.xml` (промпты — в `:core`).
- Заголовки вкладок не логируются в Logcat и не уходят никуда, кроме Termux/Claude, и только если Claude включён.
- `:core` не зависит от Android SDK: в нём нет импортов `android.*`.

## Review Focus

1. **Петля перекидывания.** Страница claude.ai, открытая с `?q=`, содержит в адресе «плохие» слова. Её надо всегда пропускать, как и страницы anthropic.com и собственный пакет. Тест: Task 3, `allowlisted hosts are never blocked`.
2. **Пустое слово или строка из пробелов в списке категории** не должна совпадать со всем подряд. Тест: Task 3, `blank keywords are ignored`.
3. **Ложные совпадения внутри слов:** «sex» не должно ловить «Sussex» и «Essex». Совпадение считается только с начала токена. Тест: Task 3, `keyword matches only at token start`.
4. **Человек набирает текст в адресной строке:** когда она в фокусе, её текст — ещё не страница, его не проверяем. Тест: Task 5, `focused url bar yields null`.
5. **Termux отсутствует, нет разрешения, Claude не залогинен или вызов завис.** Классификация должна вернуть `Verdict.Unknown` не позже чем через 30 с, без падения, а конвейер должен продолжать обрабатывать следующие вкладки. Тесты: Task 4, `remote failure yields Unknown and pipeline continues`; Task 8, `timeout yields Unknown`.

### Task 3: Модели, текст и локальное сопоставление (`:core`)

**Files:**
- Create: `core/.../model/Models.kt`, `core/.../text/Text.kt`, `core/.../match/LocalMatcher.kt`
- Test: `core/src/test/.../text/TextTest.kt`, `core/src/test/.../match/LocalMatcherTest.kt`

**Interfaces:**
- Produces:
  - `data class TabSnapshot(val packageName: String, val url: String?, val title: String?)`, `val TabSnapshot.key: String` = `"${url.orEmpty()}|${title.orEmpty()}"`
  - `data class Category(val id: Long, val name: String, val enabled: Boolean, val keywords: List<String>, val domains: Set<String>)`
  - `enum class VerdictSource { DOMAIN, KEYWORD, CLAUDE }`
  - `sealed interface Verdict { data class Block(val categoryId: Long, val source: VerdictSource) : Verdict; data object Allow : Verdict; data class Unknown(val reason: String) : Verdict }`
  - `fun normalize(s: String): String` — lowercase(Locale.ROOT), `ё→е`, trim
  - `fun tokenize(s: String): List<String>` — `normalize`, затем split по `[^\p{L}\p{N}]+`, без пустых
  - `fun extractHost(url: String): String?` — принимает адрес как со схемой, так и без неё (`pornhub.com/x`); отрезает `www.`; `null`, если в хосте нет точки
  - `object LocalMatcher { val ALLOWED_HOSTS = setOf("claude.ai", "anthropic.com"); const val OWN_PACKAGE = "app.tabguard"; fun isAllowlisted(tab: TabSnapshot): Boolean; fun match(tab: TabSnapshot, categories: List<Category>): Verdict.Block? }`

`match` проверяет только `enabled` категории, по порядку, сначала домены у всех, потом слова. Домен совпадает, если хост равен домену или оканчивается на `.домен`. Слово совпадает, если какой-то токен заголовка или адреса **начинается** с `normalize(keyword)`. Слово из нескольких токенов (`"only fans"`) совпадает, если в тексте есть такая же последовательность токенов, где каждый следующий начинается с соответствующего. Пустые слова пропускаются.

### Task 4: Цепочка классификаторов и конвейер вкладок (`:core`)

**Files:**
- Create: `core/.../classify/Classifier.kt`, `core/.../pipeline/TabPipeline.kt`
- Test: `core/src/test/.../classify/ClassifierChainTest.kt`, `core/src/test/.../pipeline/TabPipelineTest.kt`

**Interfaces:**
- Consumes: Task 3 (`TabSnapshot`, `Category`, `Verdict`, `LocalMatcher`)
- Produces:
  - `fun interface Classifier { suspend fun classify(tab: TabSnapshot, categories: List<Category>): Verdict }`
  - `class ClassifierChain(private val remote: () -> Classifier?) : Classifier`. Порядок: allow-list → `Allow`; `LocalMatcher.match` → `Block`; `remote()` равен `null` или нет включённых категорий → `Allow`; иначе ответ `remote`. Любое исключение `remote`, кроме `CancellationException`, превращается в `Unknown(e.message ?: "error")`.
  - `class TabPipeline(scope: CoroutineScope, classifier: Classifier, categories: suspend () -> List<Category>, onBlock: suspend (TabSnapshot, Verdict.Block) -> Unit, onUnknown: (String) -> Unit = {}, debounceMs: Long = 500, cacheSize: Int = 500) { fun submit(tab: TabSnapshot) }`

Поведение `TabPipeline`. Каждый `submit` отменяет ожидающую обработку и запускает новую через `debounceMs`. Если `tab.key` совпадает с ключом последней обработанной вкладки, ничего не делаем. Перед вызовом `classifier` смотрим в LRU-кэш вердиктов по `key`: кэшируются только `Allow` и `Block` с источником `CLAUDE`, а `Unknown` не кэшируется. Классификация идёт в отдельной корутине и не блокирует следующие `submit`. Если за время ответа Claude активная вкладка сменилась, `onBlock` всё равно вызывается: человек был на плохой странице.

### Task 6: Промпты: классификация и поддержка (`:core`)

**Files:**
- Create: `core/.../claude/ClassificationPrompt.kt`, `core/.../support/SupportPrompt.kt`
- Test: `core/src/test/.../claude/ClassificationPromptTest.kt`, `core/src/test/.../support/SupportPromptTest.kt`

**Interfaces:**
- Produces:
  - `object ClassificationPrompt { fun build(tab: TabSnapshot, categories: List<Category>): String; fun parse(reply: String, validIds: Set<Long>): Verdict }`
  - `object SupportPrompt { fun build(tab: TabSnapshot, categoryName: String): String; fun claudeUrl(prompt: String): String }`

`build` включает только `enabled` категории, по строке на каждую: `<id>: <name> (слова: <keywords через запятую>)`. Заголовок и адрес обрезаются до 300 символов. Текст промпта:

```
Ты фильтр самоконтроля. Определи по заголовку и адресу вкладки браузера, относится ли страница к одной из категорий.
Категории:
<строки категорий>
Заголовок: <title или «нет»>
Адрес: <url или «нет»>
Ответь ровно одним числом: номером категории или 0, если ни одна не подходит. Никакого другого текста.
```

`parse`: берёт первое целое число в ответе (`Regex("-?\\d+")`). `0` → `Allow`; id из `validIds` → `Block(id, CLAUDE)`; иначе, в том числе если числа нет → `Unknown("unparsable reply")`.

Поддерживающий промпт (`SupportPrompt.build`):

```
Я только что чуть не открыл страницу из категории «<categoryName>»: «<title или адрес>».
Я поставил себе приложение, чтобы не заходить на такие сайты. Пожалуйста, мягко и без осуждения отговори меня возвращаться туда, поддержи и помоги справиться с тягой прямо сейчас: предложи пару конкретных действий на ближайшие 10 минут.
```

`claudeUrl(p) = "https://claude.ai/new?q=" + URLEncoder.encode(p, UTF_8).replace("+", "%20")`.

### Task 8: Классификатор через Termux (`:app`)

**Files:**
- Create: `app/.../termux/TermuxClaudeClassifier.kt`, `app/.../termux/TermuxResultReceiver.kt`
- Modify: `AndroidManifest.xml` — `<uses-permission android:name="com.termux.permission.RUN_COMMAND"/>`, `<queries><package android:name="com.termux"/></queries>`, `<receiver android:name=".termux.TermuxResultReceiver" android:exported="false"/>`
- Test: `app/src/test/.../termux/TermuxClaudeClassifierTest.kt` (Robolectric)

**Interfaces:**
- Consumes: `Classifier`, `ClassificationPrompt` (Tasks 4, 6)
- Produces:
  - `class TermuxClaudeClassifier(context: Context, timeoutMs: Long = 30_000, sender: (Intent) -> Unit = { context.startService(it) }) : Classifier { fun isTermuxInstalled(): Boolean; internal fun deliver(requestId: Int, result: Bundle) }`
  - `TermuxResultReceiver` получает `EXTRA_REQUEST_ID` и бандл `result` и вызывает `deliver` у экземпляра из `AppContainer`

Интент: `action = "com.termux.RUN_COMMAND"`, `component = ComponentName("com.termux", "com.termux.app.RunCommandService")`, extras: `com.termux.RUN_COMMAND_PATH = "/data/data/com.termux/files/home/.tabguard/classify.sh"`, `com.termux.RUN_COMMAND_ARGUMENTS = arrayOf(prompt)`, `com.termux.RUN_COMMAND_BACKGROUND = true`, `com.termux.RUN_COMMAND_PENDING_INTENT = PendingIntent.getBroadcast(..., FLAG_MUTABLE)` с `EXTRA_REQUEST_ID`. В ответе: бандл `result`, в нём `stdout`, `exitCode`, `err`, `errmsg`. Перед реализацией сверить эти ключи с актуальной вики Termux (`RUN_COMMAND-Intent`).

Каждый запрос получает `CompletableDeferred` в `ConcurrentHashMap<Int, ...>` и ждёт ответа через `withTimeoutOrNull(timeoutMs)`. Результаты: таймаут → `Unknown("timeout")`; `exitCode != 0` или `err != -1` → `Unknown("termux: <errmsg или stderr, до 200 символов>")`; иначе `ClassificationPrompt.parse(stdout, ids)`. Если Termux не установлен или `startService` бросил исключение, результат `Unknown(...)`.
