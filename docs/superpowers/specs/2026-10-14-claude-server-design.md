# Спека: проверка через Claude на домашнем сервере

## Зачем

Слова, домены и встроенный список ловят не всё. Второй слой — Claude (`claude -p` под подпиской человека) — оценивает страницы, которые первый слой пропустил. Claude Code работает на домашнем Ubuntu-сервере человека; телефон и ПК обращаются к нему через Tailscale. Заменяет связку Termux + proot-Ubuntu на телефоне (30–40 с на запрос, отложено).

## Что сказал человек

- Сервер: домашний Ubuntu, Claude Code под его подпиской Pro.
- Доступ с устройств: **через Tailscale**.
- Что проверять: **новый сайт — один раз по домену (кэш 30 дней), каждый поисковый запрос — отдельно**.
- Пока Claude думает: **страница открывается сразу**, при ответе «плохо» вкладка уходит в Claude.
- Запуск на сервере: **служба systemd**.

## Предположения и решения

- Сервер используется только этим человеком; наружу (вне Tailscale) не открывается.
- Сервер на **Python 3 (только стандартная библиотека)** — есть в любой Ubuntu; Claude Code ставится официальным установщиком (`curl -fsSL https://claude.ai/install.sh | bash`), Node.js не нужен.
- Быстрый первый слой (слова, домены, встроенный список, безопасный поиск на ПК) не меняется и остаётся первым.

## Сервер `server/`

### Запуск

- `server/tabguard_server.py` — HTTP-сервис; слушает адрес и порт из `~/.config/tabguard/server.env` (`TABGUARD_HOST`, по умолчанию адрес Tailscale из `tailscale ip -4`; `TABGUARD_PORT=8787`; `TABGUARD_TOKEN`).
- systemd-служба уровня пользователя (`~/.config/systemd/user/tabguard.service`, `loginctl enable-linger`), чтобы `claude` видел вход этого пользователя; перезапуск при падении.
- `server/install.sh`: проверяет `python3` (≥ 3.10) и `tailscale`; ставит Claude Code, если его нет, и просит выполнить `claude` для входа; генерирует токен (32 байта, hex); пишет `server.env` и юнит; включает службу; печатает адрес (`http://100.x.x.x:8787`) и токен.

### API

Все запросы, кроме `GET /health`, требуют заголовок `Authorization: Bearer <токен>`; неверный/нет → `401`.

`GET /health` → `200 {"ok": true, "claude": "<claude --version>" | null}`. Без токена — только `{"ok": true}`.

`POST /classify`, тело JSON:

```json
{
  "kind": "search" | "site",
  "query": "текст запроса (для search)",
  "host": "домен (для site)",
  "title": "заголовок или null",
  "url": "адрес или null",
  "categories": [{"id": "porn", "name": "Порно", "keywords": ["..."]}]
}
```

Ответ `200 {"verdict": "block" | "allow", "categoryId": "porn" | null, "cached": true | false}`; при сбое Claude — `503 {"error": "..."}`; неверное тело — `400`.

### Кэш

SQLite-файл `~/.local/state/tabguard/cache.db`. Ключ: `kind` + (`host` для site / нормализованный `query` для search) + отпечаток категорий (хэш списка `id/name/keywords`). Срок 30 дней. Кэшируются только `block`/`allow`, не ошибки.

### Вызов Claude

`claude -p --model haiku --tools "" --system-prompt "Ты классификатор. Отвечай только числом."` с переменными `DISABLE_AUTOUPDATER=1`, `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1`. Промпт — тот же формат, что `ClassificationPrompt` в Android (`core/.../claude/ClassificationPrompt.kt`): категории `N: имя (слова: …)`, заголовок, адрес/запрос, «Ответь ровно одним числом…»; категории нумеруются 1..n, ответ переводится обратно в `id`. Разбор ответа — первое целое число: `0` → allow, номер категории → block, иначе ошибка.

Одновременно выполняется один вызов `claude`; одинаковые ключи, пришедшие во время вызова, ждут его результата. Таймаут вызова 60 с.

## Клиенты (телефон и расширение)

Общее поведение:

1. Первый слой без изменений; если он блокирует — сервер не спрашивается.
2. Иначе, если «Проверка через сервер» включена: определить тип —
   - **search**: адрес — страница поиска Google/Яндекса/Bing/DuckDuckGo с непустым запросом (`q`/`text`) → `query` = текст запроса; на телефоне также, если в адресной строке не хост, а просто текст → `query` = этот текст;
   - **site**: иначе → `host` = домен без `www.`;
   - страницы claude.ai/anthropic.com, служебные и не-http — не отправляются.
3. Страница не задерживается. При ответе `block` — если вкладка всё ещё на той же странице — обычная блокировка (на телефоне «Назад» + Claude + счётчик; на ПК переход в Claude + буфер + счётчик).
4. Сервер недоступен / `401` / `503` / таймаут 15 с → пропуск без блокировки; текст ошибки показывается в настройках («Сервер недоступен: …»).
5. Отправляемые категории — включённые, со словами пользователя (без встроенного словаря — он уже проверен локально).

### Телефон

- Блок Termux заменяется блоком **«Проверка через сервер»**: переключатель, «Адрес сервера», «Токен», «Проверить связь» (`GET /health` с токеном → «OK, Claude <версия>» или ошибка).
- `TermuxClaudeClassifier`, `TermuxResultReceiver`, разрешение `com.termux.permission.RUN_COMMAND`, `termux/classify.sh`, `docs/termux-setup.md` удаляются.
- HTTP через `HttpURLConnection` (без новых библиотек).

### Расширение

- В настройках тот же блок «Проверка через сервер».
- Доступ к серверу: `optional_host_permissions: ["http://*/*"]`; при сохранении адреса запрашивается `chrome.permissions.request({origins: ["http://<host>:<port>/*"]})` — одно окно Chrome; без разрешения проверка не включается.
- Ответы сервера дополнительно кэшируются в памяти фонового скрипта на время его жизни.

## Проверка

- Сервер: `python3 -m unittest` — подменённый `claude` (скрипт-заглушка), кэш, очередь/склейка, токен, разбор ответа, таймаут.
- Расширение: юнит-тесты определения типа (search/site); сквозной Playwright-тест с поддельным сервером (блок по ответу, `allow`, недоступный сервер, неверный токен).
- Телефон: Robolectric-тесты HTTP-клиента против локального `ServerSocket`.
- Вживую с настоящим Claude — человек по чек-листу `docs/manual-test-server.md`.

## Вне рамок

- Доступ к серверу вне Tailscale, несколько пользователей.
- Проверка содержимого страниц (картинок, текста) — только заголовок/адрес/запрос.
- Задержка страницы до ответа Claude.
